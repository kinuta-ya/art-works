# 音楽プレイヤー 要求定義

最終更新: 2026-09-27

## 1. ビジョン

Apple Music のように気持ちよく使える画面を持ちながら、**音に余計なものを足さない**音楽プレイヤーを作る。
音源が持っているダイナミクス（強弱・余韻・静けさ）をそのまま DAP とイヤホン・ヘッドホンに届ける。
そのうえで、「使う人が自分で選んだときだけ」EQ・聴力補正・ノンストップ再生といった加工ができるようにする。

## 2. 前提

| 項目 | 決定内容 |
|---|---|
| 対象端末 | Shanling M8T（Android、真空管搭載 DAP）専用 |
| 本番プラットフォーム | Android ネイティブアプリ |
| 音源 | SD カードに保存されたローカル音楽ファイル（ストリーミングは対象外） |
| 進め方 | まず Web 版で画面と機能のデモを作り、操作感と仕様を固めてから Android 版を作る |

## 3. 対象ハードウェア（Shanling M8T）

公式発表の仕様（公式サイトの仕様を転載した販売店・レビューで確認）。付属のクイックスタートガイド（M8T说明书 V1.0、中英日）も確認したが、音質の仕様表は載っていない。

| 項目 | 値 |
|---|---|
| DAC | AKM AK4191EQ ×2（デジタル処理・ΔΣ変調）＋ AK4499EX ×2（アナログ変換）。左右独立 |
| 真空管 | Raytheon JAN6418 ×2（防振構造） |
| 出力モード | トランジスタ / 三極管（Triode）/ ウルトラリニア（Ultra-Linear） |
| 対応フォーマット | PCM 768kHz/32bit、DSD1024（DST 圧縮の ISO を含む） |
| 出力（トランジスタ） | バランス 1125mW、シングルエンド 500mW（32Ω） |
| 出力（真空管） | バランス 950mW、シングルエンド 420mW（32Ω） |
| 出力インピーダンス | 1Ω 未満（真空管モードを含む） |
| 周波数特性 | 20Hz〜40kHz（±0.2dB） |
| THD+N | シングルエンド 0.0007%、バランス 0.0005% |
| S/N・ダイナミックレンジ | 124dB（シングルエンド・トランジスタ）、真空管モード 123dB（DAC チップ単体は 135dB） |
| ゲイン | 高 / 中 / 低 |
| USB DAC | XMOS XU316（PCM 768kHz/32bit、DSD512） |
| SoC・メモリ | Qualcomm Snapdragon 665、RAM 6GB、ストレージ 128GB |
| OS・画面 | Android 13、6 インチ 2160×1080 |
| バッテリー | 8350mAh（シングルエンド 15.5 時間、バランス 13 時間） |
| ビットパーフェクト | 「Android Global Lossless Output」：サードパーティのアプリでもビットパーフェクトで出力するとされる |
| 端子 | 4.4mm バランス、3.5mm ヘッドホン / ライン出力（兼用）、USB Type-C、microSD（最大 2TB） |
| 物理操作 | 音量ホイール（電源ボタン兼用）、曲戻し / 再生・停止 / 曲送りボタン（曲戻し・曲送りは長押しで早戻し・早送り）、状態表示ランプ |
| 無線 | Bluetooth（aptX HD 対応） |

クイックスタートガイドから分かる、アプリに関係する点:

- 音量はホイールで調整する。アプリ内のデジタル音量は既定で 100%（素通し）のままにし、ホイールでの調整を前提にする
- 物理ボタンの曲戻し・曲送りの長押しが早戻し・早送りに割り当てられている。Android 版はメディアボタンの長押し（シーク）にも対応する
- 3.5mm 端子はライン出力を兼ねる。ライン出力として使う場合はデジタル音量・EQ・ReplayGain をすべて外すのが望ましい
- 音楽は microSD（最大 2TB）に置く前提。大きなライブラリでも取り込みを軽く保つ（変更分だけ読み直す、F1-7）

設計への影響:

- 「Android Global Lossless Output」が公式の説明どおりに働くなら、Android 版は通常のオーディオ出力に音源本来のサンプルレートでデータを渡すだけで素通しになる。実機で確認する
- DAC の性能（S/N 124dB 前後）は 16bit 音源のダイナミックレンジ（約 96dB）を大きく上回る。デジタル音量や EQ を使うときは、24bit 以上で出力しディザをかける意味がある
- 最大 768kHz・DSD1024 はブラウザでは扱えないため、Android 版の範囲とする
- 聴力補正のプロファイルは「イヤホン × 3 つの出力モード」で分ける（F5-3）

参考: Headfonics / Shenzhen Audio / Linsoul / Audiophonics / e☆イヤホン / MUSIN（日本代理店）の各製品ページとレビュー。

## 4. 基本原則

1. **標準は素通し（ビットパーフェクト）**
   音量処理・サンプルレート変換・ダイナミクス圧縮・ラウドネス処理をしない。
2. **加工は明示的なオプトイン**
   EQ・聴力補正・クロスフェード・デジタル音量は、使う人がオンにしたときだけ効く。
3. **今の音の状態を常に見せる**
   「素通し中」「加工中（EQ）」などを、再生画面で一目でわかるようにする。
4. **加工するときも劣化を最小限にする**
   浮動小数点で処理し、先に音量を下げる（自動プリアンプ）ことで音割れを防ぐ。整数出力のときはディザをかける。

## 5. 機能要求

### F1. ライブラリ

- F1-1: SD カード上のフォルダーを指定して音楽ファイルを取り込む
- F1-2: 対応形式は FLAC / ALAC / WAV / AIFF / MP3 / AAC / DSD（DSF・DFF）。DSD は Android 版で対応する
- F1-3: タグ（曲名・アーティスト・アルバム・アルバムアーティスト・トラック番号・ディスク番号・年・ジャケット）を読み取る
- F1-4: タグが無いときはフォルダー名とファイル名から推定する
- F1-5: フォルダー内の `cover.jpg` / `folder.jpg` などをジャケットとして使う
- F1-5b: ジャケットが無いアルバムには、ジャンルの系統（ジャズ・クラシック・ロックなど 10 系統＋その他）ごとの作風で代わりのジャケットを作る。テーマに関係なく同じ見た目にする。系統のベース画像をアルバム名で選び分け・反転・切り抜きし、下の帯にアルバム名を描く
- F1-6: アルバム、アーティスト、曲の一覧と検索
- F1-8: ジャンル一覧。ジャンルごとに、そのジャンルのジャケットを組み合わせたサムネイルとジャンル名を並べた選択画面にする
- F1-7: 取り込み結果を保存し、次回起動時は変更分だけ読み直す（Android 版）

### F2. 再生（素通し）

- F2-1: 音源のサンプルレートとビット深度のまま出力する（Android 版ではビットパーフェクト出力経路を使う）
- F2-2: 再生、一時停止、前後の曲へのスキップ、シーク、シャッフル、リピート
- F2-3: 再生キューの表示と並べ替え
- F2-4: 信号経路の表示（例: `FLAC 96kHz/24bit → 出力 96kHz ・ 素通し`）
- F2-5: 音量は原則として DAP 側のハードウェア音量で調整する。アプリ内のデジタル音量を 100% 以外にしたときは「加工中」と表示する
- F2-6: ロック画面や通知からの操作、ヘッドセットボタンと M8T 本体の物理ボタンへの対応（曲戻し・曲送りの長押しで早戻し・早送り）

### F3. ノンストップモード

2 つのモードから選べるようにする。

**F3-A. ギャップレスモード（標準）**
- 曲の境目に無音を 1 サンプルもはさまない
- MP3 や AAC のエンコーダー遅延とパディングを除去する（LAME / iTunNORM 情報を使う）
- 音には一切手を加えない

**F3-B. スマートクロスフェードモード**
- 曲の頭と終わりの無音を検出して飛ばす
- フェードアウトしていく曲では、そのフェード区間を検出し、それに合わせてクロスフェードの長さを決める
- 等パワー（equal-power）カーブでフェードする
- 2 曲の音量差をそろえる（最大 ±6dB、オプション）
- 同じアルバムの連続したトラックでは、自動でギャップレスに切り替える（ライブ盤やコンセプトアルバムを壊さないため）
- 将来の拡張: テンポやキーを解析して、つなぐ位置を選ぶ

### F4. EQ（オプトイン）

- F4-1: パラメトリック EQ（ピーキング / ローシェルフ / ハイシェルフ、周波数・ゲイン・Q）
- F4-2: プリセットと、ユーザー自作プリセットの保存
- F4-3: AutoEQ 形式（`ParametricEQ.txt`）の読み込み
- F4-4: 合成した周波数特性をグラフで表示する
- F4-5: 自動プリアンプ。最大のブースト量ぶん先に音量を下げ、音割れを防ぐ
- F4-6: ワンタップのバイパス（オフにすると処理経路から完全に外れる）
- F4-7: ReplayGain（オフ / トラック / アルバム、既定はオフ）。ゲイン調整だけで、ダイナミクスは圧縮しない。基準は -18 LUFS。タグ（FLAC の Vorbis コメント、MP3 の TXXX）があれば優先し、無ければ再生前に EBU R128 で解析して求める。音割れ防止（ピークが 0dBFS を超えない量まで）を既定でオンにする

### F5. 聴力テストと自動補正（オプトイン）

- F5-1: 左右別、周波数別（250Hz〜12kHz）に聞こえる最小音量を測る
- F5-2: 標準的な聴覚しきい値との差をもとに補正カーブを作る。補正の強さと最大ブースト量は調整できるようにする
- F5-3: プロファイルを「イヤホン・ヘッドホン × 出力モード（トランジスタ / 三極管 / ウルトラリニア）」の組み合わせごとに保存する。M8T は真空管モードでも出力インピーダンスが 1Ω 未満のため、アンプとイヤホンの組み合わせによる周波数特性の変化は小さい
- F5-4: 医療用の検査ではないことを明示する。テスト音は小さい音から始める

### F6. 分析と表示

- F6-1: DR メーター。foobar2000 の DR Meter と同じ方式（3 秒ブロックの RMS 上位 20% と 2 番目のピークの比）。曲とアルバムの DR を表示し、14 以上・8〜13・7 以下で色分けする
- F6-2: 波形シークバー。曲全体の波形をシークバーにし、再生済みの部分を色で示す
- F6-3: 高域の判定。スペクトルから高域の上限（急に落ちる周波数）を検出し、ハイレゾのアップサンプリング（24kHz 付近で切れている）や、圧縮音源からの変換（16〜20kHz で切れている）の可能性を示す。24bit なのに下位 8bit が空の音源も検出する。古い録音など、正規の音源でも同じ結果になることがある旨を添える
- F6-4: スペクトログラム。判定の根拠を目で確かめられるようにし、検出した上限を点線で示す
- F6-5: VU メーター。左右のアナログ針（0VU = -18dBFS、電圧に比例する本物と同じ目盛り）。信号をのぞくだけで音には手を加えない。設定で非表示にできる
- F6-6: アルバム画面の「アルバムを解析」で、全曲を音源本来のサンプルレートでデコードして解析する。結果は端末に保存する

## 6. デザイン

外観はテーマで切り替えられる（設定 → テーマ）。ミッドセンチュリー（既定、OS のライト/ダークに追従）、バウハウス、スイス・スタイル、アール・デコ、メンフィス、Y2K、ミニマリズム、グラスモーフィズム、ニューモーフィズム、ヴェイパーウェイブの 10 種類。テーマは色・書体・角の形・影・背景の模様をトークンで差し替える仕組みで、画面の構造と操作は共通。フォントは選んだテーマの分だけ読み込む。

既定のミッドセンチュリーの方針:

- ミッドセンチュリーモダン。生成りの紙（ライト）とウォルナット材（ダーク）を地に、からし色・焼けたオレンジ・ティール・オリーブ
- 書体は幾何学的なサンセリフ（Jost）と、数値用の等幅（DM Mono）。円・アーチ・アトミックスターをモチーフにする
- 再生画面はハイファイのレコードプレーヤー。ジャケットは盤の中央ラベルになり、再生中は 33⅓ 回転で回る。再生するとトーンアームが盤の上に移動する。タップで再生と一時停止を切り替える
- ジャンル一覧は、ジャンルごとの色面カードに、ジャケットを入れたアーチ窓とジャンル名を並べる
- インタラクションは軽量にする。transform と opacity だけを使い、操作の邪魔をしない。OS の「視差効果を減らす」設定ではすべて止める

## 7. 非機能要求

- ギャップレス再生の継ぎ目の誤差は 0 サンプル（Android 版）
- 大きいライブラリ（数万曲）でも一覧がなめらかにスクロールすること
- 設定・プロファイル・再生位置を端末内に保存する。ネットワークは使わない
- 画面は M8T の縦長画面に最適化する。暗い場所でも見やすいダークテーマにする

## 9. Web デモの範囲と限界

`public/index.html` を開くと動く。ビルドは不要。

**できること**
- フォルダーを選んでライブラリを作る（タグ解析: FLAC / MP3（ID3v2）/ M4A / WAV）
- 再生、キュー、ギャップレスモード、スマートクロスフェードモード
- パラメトリック EQ、AutoEQ 読み込み、聴力テスト、補正プロファイル
- 信号経路の表示
- 音源ファイルが無くても試せる、合成音によるデモアルバム

**Web の限界（Android 版で解決すること）**
- ブラウザの出力は OS のミキサーを通るため、ビットパーフェクトにはならない
- 出力サンプルレートは音源に合わせて切り替えを試みる。ただし、最終的に OS 側でリサンプルされることがある
- ALAC と DSD の再生はブラウザ次第（Chrome は非対応）
- MP3 と AAC のエンコーダー遅延の除去はブラウザのデコーダー任せ
- 再読み込みするとライブラリが消えるので、フォルダーを選び直す必要がある
